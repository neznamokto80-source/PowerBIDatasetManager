## 2. Добавление общего фильтра по названиям датасетов

### Требования
- Текстовое поле фильтра, которое фильтрует датасеты по названию (регистронезависимый поиск).
- Расположение: сверху под кнопками справка (в верхней части центральной панели, под панелью инструментов).
- Начало фильтра должно быть на уровне начала вкладки обзор (выравнивание по левому краю с вкладкой).
- Фильтр должен работать в реальном времени (при вводе текста).

### Изменения в UI

1. **Модификация `src/ui/ui_panels.py` - функция `create_overview_tab`**:
   - Добавить горизонтальный layout между статистикой и таблицей датасетов.
   - Включить QLabel "Фильтр по названию:" и QLineEdit.
   - Подключить сигнал `textChanged` к методу `apply_dataset_name_filter`.

2. **Создание нового метода фильтрации**:
   - В классе `FilteringMethods` (или в `data_filtering_ops.py`) добавить метод `apply_dataset_name_filter(text: str)`.
   - Метод должен фильтровать `self.main_window.datasets` по полю `name` (или `displayName`).
   - Обновлять таблицу датасетов и дерево датасетов в левой панели.

3. **Интеграция с существующей системой фильтров**:
   - Существующие фильтры (чекбоксы) должны комбинироваться с текстовым фильтром.
   - Логика фильтрации должна быть в одном месте (например, в `apply_filters`).

### Примерный код

```python
# В create_overview_tab, после статистики
filter_layout = QHBoxLayout()
filter_label = QLabel("Фильтр по названию:")
self.main.dataset_name_filter = QLineEdit()
self.main.dataset_name_filter.setPlaceholderText("Введите часть названия датасета...")
self.main.dataset_name_filter.textChanged.connect(self.main.apply_dataset_name_filter)
filter_layout.addWidget(filter_label)
filter_layout.addWidget(self.main.dataset_name_filter)
filter_layout.addStretch()
layout.addLayout(filter_layout)
```

## 3. Рефакторинг функционала расписания

### Текущее состояние (после рефакторинга)
- Редактирование расписания осуществляется через отдельное диалоговое окно `ScheduleEditorDialog`.
- Вызывается по кнопке "Редактировать расписание" (предположительно).

### Новые требования
- Вынести функционал расписания из отдельного окна на вкладку детали.
- Добавить всплывающее окно с деталями расписания (для просмотра).
- Функционал изменения расписания должен располагаться под кнопками "Включить обновление/отключить обновление/Запустить обновление".
- Выбор времени через выпадающие списки для часов и минут в формате 24 часов.

### Реализованные изменения

1. **Модификация вкладки "Детали"** (`create_details_tab` в `ui_panels.py`):
   - Добавлена группа "Управление расписанием" (изначально скрыта).
   - Элементы группы:
     - 7 чекбоксов дней недели (понедельник-воскресенье)
     - Поле ввода времени (формат ЧЧ:ММ) и кнопки "Добавить"/"Удалить"
     - Список выбранных времен (`QListWidget`)
     - Выпадающий список часовых поясов (редактируемый `QComboBox`)
     - Выпадающий список уведомлений (`MailOnFailure`, `MailOnCompletion`, `NoNotification`)
     - Чекбокс "Расписание включено"
     - Кнопки "Сохранить расписание" и "Удалить расписание"
   - Кнопка "Расписание…" переключает видимость этой группы.

2. **Новые методы в `main_window.py`**:
   - `toggle_schedule_group()` - переключение видимости группы
   - `add_schedule_time()` - добавление времени из поля ввода
   - `remove_schedule_time()` - удаление выбранного времени
   - `save_schedule()` - сбор данных из UI и вызов `refresh_operations.update_refresh_schedule`
   - `delete_schedule()` - удаление расписания через `refresh_operations.disable_auto_refresh`
   - `load_schedule_to_ui(schedule_data)` - загрузка данных расписания в UI элементы
   - `_clear_schedule_ui()` - сброс UI к состоянию по умолчанию

3. **Обновление `refresh_operations.py`**:
   - Добавлен метод `update_refresh_schedule(workspace_id, dataset_id, payload)` для сохранения расписания через `RefreshManager`.

4. **Интеграция с загрузкой данных**:
   - Метод `update_dataset_details` в `data_loading_ops.py` теперь вызывает `load_schedule_to_ui` для отображения текущего расписания датасета.

### Логика работы
- При выборе датасета загружается его расписание (если есть) и отображается в элементах управления.
- Пользователь может изменить дни, времена, часовой пояс, уведомления и состояние.
- При нажатии "Сохранить расписание" формируется payload и отправляется в API.
- При нажатии "Удалить расписание" расписание отключается.

```

Список времен:
  09:00
  18:00
Часовой пояс: [UTC+05:00 Екатеринбург]
Уведомления: [MailOnFailure]
[✓] Расписание включено
[Сохранить расписание] [Удалить расписание]
```

## Добавление чекбокса включения сохранения сырых логов

### Требования
- Добавить чекбокс в UI для включения/отключения сохранения сырых логов (отладочных данных) API-запросов и ответов.
- Логи должны сохраняться в каталог `debug/` в корне проекта (на том же уровне, что и `src/`, `docs/`).
- Содержимое каталога `debug/`  должно игнорироваться Git ( добавлять в `.gitignore`).

### Текущее состояние
- Функционал сохранения сырых данных уже реализован в `powerbi_client.py` через параметр `debug_data_path`.
- Сейчас `debug_data_path` устанавливается как `None` (отключено) в `connection.py`.

### Изменения

1. **Создание каталога `debug/`** в корне проекта (если не существует).
2. **Добавление чекбокса в UI**:
   - Вариант размещения: в левой панели под группой "Мониторинг" или в отдельной группе "Отладка".
   - Чекбокс с текстом "Сохранять сырые логи (debug)".
   - При включении устанавливать `debug_data_path = "debug/"` в `PowerBIClient`.
   - При отключении устанавливать `debug_data_path = None`.
3. **Сохранение состояния** между сеансами (через настройки приложения или переменную).
4. **Обновление `powerbi_client.py`** для использования пути относительно корня проекта.
5. **Проверка `.gitignore`**: убедиться, что `debug/`  добавлен в игнорируемые папки.

### Примерный код добавления чекбокса

```python
# В create_left_panel (ui_panels.py) добавить группу "Отладка"
debug_group = QGroupBox("Отладка")
debug_layout = QVBoxLayout()
self.main.debug_checkbox = QCheckBox("Сохранять сырые логи (debug)")

debug_layout.addWidget(self.main.debug_checkbox)

```

### Логика переключения
- При изменении состояния чекбокса обновлять `debug_data_path` в `PowerBIClient` (возможно, потребуется пересоздание клиента).
- Если клиент уже создан, обновить его свойство `debug_data_path`.
